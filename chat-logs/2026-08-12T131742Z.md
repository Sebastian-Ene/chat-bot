Four real alternatives, and one of them is better than the volume.

**1. Bind mount a host directory** (`./var/ingest:/state`) — same persistence, but visible on the host so you can inspect or delete the manifest to force a re-ingest. Consistent with how `./logs` already works. Watch the uid-1000 ownership on the host dir.

**2. A Qdrant collection for the manifest** — one point per document, payload carries hash/timestamp/counts. Keeps state next to the vectors, so wiping the DB wipes the manifest too. Slightly awkward: Qdrant wants a vector per point, so you'd carry a dummy.

**3. No manifest at all — derive it from Qdrant.** The chunk payload spec *already* includes `doc_id` and `doc_content_hash`. So "what is indexed, and at which version" is answerable directly from the collection: scroll distinct `(doc_id, doc_content_hash)` pairs and compare against the files on disk. New, changed, unchanged and deleted all fall out of that comparison.

**4. No persistence** — re-ingest everything each run. Rejected: §6.1 requires incremental ingestion.

## Why I'd now pick 3 over the volume

A separate manifest file can **disagree with reality**. Wipe the Qdrant volume but keep the state volume, and the app believes 25 documents are indexed when the collection is empty — nothing re-ingests, and retrieval silently returns nothing. That's a genuinely nasty failure because everything *looks* fine. Deriving from Qdrant makes that state unrepresentable.

It also deletes a component: no extra volume, no extra file format, no ordering rule about writing the manifest only after indexing succeeds — because the indexed chunks *are* the record.

**The one thing it needs to be correct:** upsert all of a document's points in a **single** Qdrant call, so a document is atomically present-at-hash-X or not. Partial writes would otherwise let a half-indexed document look complete. Qdrant upserts are atomic per request, so that's a constraint on how we write, not extra machinery.

**Costs, honestly:** a scroll over the collection per run (trivial at 25 documents; wants a payload index on `doc_id` at real scale), and no place to record run metadata like "attempted and failed" — which we don't currently need. It also means the plan can only be computed with Qdrant up, which is already a hard startup requirement.
