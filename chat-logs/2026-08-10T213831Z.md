Three things to settle first, because they change the work:

**1. Decorator vs FastAPI dependency.** You said decorator. FastAPI's native mechanism for "attach to any future endpoint" is a dependency — `Depends(verify_token)` per endpoint, or `dependencies=[...]` on a whole router, and it shows up in the OpenAPI schema. A plain decorator works but sits outside that machinery (needs `functools.wraps` and care not to break signature introspection), and can't be applied router-wide.
- **a)** Dependency — idiomatic, router-wide, self-documenting. **Recommended.**
- **b)** Literal decorator `@require_token`, as you wrote it.

**2. Where the secret comes from.** A required `JWT_SECRET` means your existing `.env` stops booting the app until you add one, and cuts against the one-command `docker compose up` in §9. I'd default it to a per-process random value, overridable via `.env`. Caveat I'd document: with multiple workers/containers each process signs differently, so anything beyond one process **must** set `JWT_SECRET` explicitly or tokens will randomly fail.

**3. Token expiry is user-visible.** At a 30-minute TTL, a page left open then used will 401. I'd have the frontend show "Your session expired — please reload the page." rather than the generic error. A refresh endpoint would avoid it entirely but is beyond what you asked.

Confirm, and answer 1 (a or b) — I'll take my recommendations on 2 and 3 unless you say otherwise.

**`app/security.py`** — `issue_token()` (HS256, `iat`/`exp`) and `verify_token()` as a FastAPI dependency. Rejections are a flat 401 with `WWW-Authenticate: Bearer`; the actual reason is logged, not returned. Module docstring states up front that this isn't authentication.

**`app/config.py`** — `jwt_secret: SecretStr` (required, one value for the whole app) and `jwt_ttl_seconds: int = 300`.

**Wiring** — `/api/chat` opts in with `dependencies=[Depends(verify_token)]`, per-endpoint as you asked. `pages.py` mints a token per render into `<meta name="chat-token">`; `chat.js` sends it as a Bearer header and shows "Your session expired. Please reload the page." specifically on 401.

**`.env.example`** — `JWT_SECRET` (with a generation one-liner) plus the previously-undocumented optional settings.

**Tests** — 12 in `test_security.py` (round-trip, claim TTL, expired, wrong secret, tampered, 5 malformed-header cases, case-insensitive scheme, no reason leaked), 3 endpoint cases, 2 page cases, and an e2e proving the 401 message renders in a real browser.

Four decisions worth surfacing:

- **`chat.js` now reads the meta tag per request** rather than caching it at load. I changed this because the e2e test couldn't otherwise exercise the 401 path — but it's also what a refresh endpoint would need, so it isn't test-only scaffolding.
- **PyJWT warned the test secret was under 32 bytes** (RFC 7518 §3.2 for HS256). I lengthened the test secrets rather than silencing the warning. Your real `JWT_SECRET` should be ≥32 bytes — the `.env.example` comment gives the command. I did *not* add a minimum-length check on the setting; say the word if you want one, since a short secret is exactly what makes signature checking pointless.
- **Token check runs before body validation** — there's a test pinning that, so an unauthenticated caller learns nothing about the request schema.
- `tests/api/test_chat_page.py` collided with the e2e file of the same name (pytest module-name clash, no `__init__.py`); it's `tests/api/test_page_token.py`.

**The app will not boot until you add `JWT_SECRET` to your `.env`** — that's the fail-fast behaviour you asked for, but it means an existing `.env` needs updating before the next run.
