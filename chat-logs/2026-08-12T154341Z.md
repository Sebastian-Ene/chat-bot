Chunking only, then. Noted for later: dense + sparse.

**`app/rag/ingest/chunk.py`**

- `HybridChunker(tokenizer=HuggingFaceTokenizer(AutoTokenizer("BAAI/bge-m3"), max_tokens=512), merge_peers=True)`, built once per process behind `lru_cache` like the converter.
- The tokenizer must be BGE-M3's, not a default — chunk boundaries have to be measured in the same tokens the embedder will count, or a "512-token" chunk silently overflows at embed time.
- `chunk(parsed: ParsedDocument) -> list[Chunk]` and `chunk_all(parsed_documents)` mirroring `parse`/`parse_all`.

**The `Chunk` dataclass** carries two texts, deliberately:
- `embed_text` — `chunker.contextualize(chunk)`, which prepends the heading path. This is what gets embedded, so a chunk reading "Reset the hub" is findable as belonging to *Troubleshooting → Hub offline*.
- `text` — the raw chunk, what gets shown to the LLM and cited. Contextualised text in the prompt would put synthetic heading breadcrumbs into the answer.
- Plus `doc_id`, `doc_content_hash`, `chunk_index`, `headings`, `page_numbers`, `source_format`.

**Provenance**: page numbers come from `chunk.meta.doc_items[].prov[].page_no`, deduplicated and sorted. PDF-only — DOCX and HTML chunks get an empty list, and the citation format has to tolerate that rather than treat it as an error.

**Tables**: `HybridChunker`'s serializer emits the table with its header, and a table too large for `max_tokens` is split with the header repeated. A page-spanning table arrives as two separate table objects (the spike finding), so it will produce two chunks that each look complete — accepted, not worked around.

**Logging**: DEBUG per document with the chunk count and token distribution; the run summary gains a chunk total.

**One thing this forces**: the BGE-M3 tokenizer is a HuggingFace download. Right now it would be fetched at runtime, which contradicts the baked-models decision we just made — so the Dockerfile warmup step needs to pull the tokenizer too. Small change, but it belongs in this step rather than being discovered later.

**Tests**
- Fast (`tests/ingest/test_chunk.py`): chunker built once; `chunk_index` is sequential from 0; `embed_text` differs from `text` when headings exist; page numbers deduplicated and sorted; empty page list for a non-PDF chunk; a document that yields no chunks returns an empty list rather than raising. Stubbed chunker, no models.
- Real (`tests/ingest/test_chunk_documents.py`, marked `docling`): chunk the German technical PDF and the FAQ HTML — assert chunks exist, no chunk exceeds 512 tokens by BGE-M3's own tokenizer, heading paths are populated, and PDF chunks carry page numbers while HTML ones don't.

Then a real run over all 20 documents to report chunk counts per format and the added wall time.

Two calls I'd make unless you disagree: `max_tokens=512` (BGE-M3 handles 8192, but large chunks dilute the embedding and hurt precision), and keeping both texts rather than embedding the raw chunk.

## assistant — 18:39

`# noqa` is a linter suppression comment — "no quality assurance," i.e. don't flag this line. `E402` is the specific rule: *module level import not at top of file*.

Normally all imports go at the top. In `parse.py`, `chunk.py`, `runner.py` and `__main__.py` they can't, because of this:

```python
os.environ.setdefault("TORCHDYNAMO_DISABLE", "1")

from docling.document_converter import DocumentConverter  # noqa: E402
```

That env var has to be set *before* torch is imported, since torch reads it at import time to decide whether to enable the inductor/triton JIT — which needs a C compiler the container doesn't have. Move the import above the `setdefault` and every conversion fails. So the imports are deliberately below a statement, and the comment tells the linter that's intentional rather than sloppy.

Worth flagging: we don't actually have a linter configured in this project — no ruff or flake8 in the dev dependencies, nothing in `pyproject.toml`. So right now these comments are inert; they're documentation of intent that would start working the moment linting is added. If you'd rather not carry dead annotations, the alternative is dropping them and letting whoever adds ruff deal with it then — though they'd have to rediscover why the imports are placed that way.
