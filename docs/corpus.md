# Test document corpus

> What the corpus contains and why. The decisions behind it are in
> `docs/considerations.md`, the specification in `docs/requirements.md` §4.

Generated by `uv run python -m scripts.generate_corpus`. Output is committed so
the deliverable is self-contained; regeneration is byte-identical, which keeps
content hashes stable, so re-ingesting an unchanged corpus is a no-op.

**`corpus/` is generated output only** — nothing hand-written lives there, so it
can be deleted and rebuilt at any time.

All content is about **Aurora Home**, an invented smart-home company. Nothing
here describes a real product or organisation.

## Layout

```
corpus/
  docs-initial/
    coverage/          hand-authored, carries the deliberately-hard aspects
      images/          only what HTML needs — PDF and DOCX embed their figures
    bulk/              distractors
  docs-later/          second batch, for incremental ingestion
  golden_qa.json
```

The tree is nested on purpose: the ingester is expected to walk it recursively
rather than read one flat directory.

Sources live under `scripts/corpus/` and are **not** part of the corpus —
`content/` holds the Markdown the bulk is authored in, `images/` the generated
figures (gitignored; regenerated on demand).

**25 documents: 20 initial + 5 later.** 13 EN, 11 DE, 1 mixed ·
PDF ×12, DOCX ×7, HTML ×6.

Two authoring paths:

- **Coverage** — hand-authored Python modules, because the hard aspects need
  precise layout control.
- **Bulk** — Markdown with front matter, rendered by `markdown_kit` +
  `renderers`. `layout: report | manual | brief` picks a visual treatment so the
  bulk doesn't share one fingerprint. The error-code reference is generated
  combinatorially rather than written by hand.

Check the golden set against the documents with
`uv run python -m scripts.check_corpus`.

**Naming note:** `bulk/` is not "answers nothing" — the regional addenda are
authoritative for regional questions, and the error-code reference answers
`qa-021`. The split is by authoring role, not by whether a document holds
answers.

## Bulk — `docs-initial/bulk/` (15)

Regional service addenda (CH, AT, UK, Benelux), release notes (3.9 → 4.2),
troubleshooting articles, the automations guide, the energy-report explainer, the
accessory catalogue, the installer programme, and the error-code reference.

They carry **near-miss** content on purpose: the Swiss addendum gives a 14-day
return window against the general 30, the 3.9 notes state a 32-device limit
against the current 64, and the UK addendum denies free shipping that the general
policy grants. Retrieving the plausible-but-wrong document is the failure mode
worth measuring.

`fehlercode-referenz-de.pdf` is the long document — **25 pages**, ~350 codes in
tables that span page breaks with the header repeating.

Initial set: 20 documents · 10 EN, 9 DE, 1 mixed.

## Later batch — `docs-later/` (5)

Release notes 4.3, the privacy policy, security advisory AH-SA-2026-01, the
maintenance-contract terms, and the webhooks integration guide. New topics, not
revisions — nothing here contradicts the initial set, so existing golden answers
stay valid.

Authored the same way as the bulk, routed by `batch: later` in the front matter.

**This makes incremental ingestion testable, not just demonstrated.** The five
`batch: later` golden questions must be **declined as unanswerable** before this
batch is ingested and **answered** afterwards. `check_corpus.py` enforces the
split: a `later` question answered by an initial document, or vice versa, is a
reported problem.

A superseding document (a warranty revision with different numbers) would be a
sharper recency test, but it would make several existing golden answers
ambiguous. Worth adding deliberately as a conflict test rather than smuggling it
in here.

## Golden Q&A set

`golden_qa.json` — 26 questions (21 initial + 5 later), each naming the document
and element the answer lives in, and carrying a `batch`. That is the ground truth for recall@k and MRR, and it is hand-written
rather than derived from the documents: a set derived by the same code that wrote
the documents would only prove the code is self-consistent.

| Type | Count | Tests |
|---|---|---|
| `table_only` | 8 | Answer exists only inside a table — one is deep in the 25-page reference |
| `near_miss` | 5 | Another document holds a plausible but wrong answer |
| `image_only` | 3 | Answer legible only inside a figure — needs image description and OCR |
| `prose` | 3 | Plain single-hop baseline |
| `unanswerable` | 3 | Must be declined, not invented — one carries a false premise |
| `cross_lingual` | 2 | Question language differs from the document answering it |
| `multi_hop` | 2 | Requires combining two documents; neither states the answer |

## Known gaps

- No scanned or image-only page — digital-native only, as specified.
- Two-column blocks in bulk documents are fenced by page breaks (a ReportLab
  constraint), so those pages end early; DOCX ignores the directive entirely.
- Most bulk documents carry no figure, so the corpus-wide figure count is low
  (6 figures across 25 documents), even though 4 of the 6 are captioned.
